# 13 · 动态新增对象（图谱模式层更新）

> 对应 `Lab4/对象化和标签.md` 里"随着用户需求/数据不断加入，数据图谱能够动态新增"（L49）
> 与"以对象为中心的图谱是动态构建的"（L57）。补的是**模式层**：不只更新实例，而是让对象模型能长。

## 1. 问题

之前"能更新"只到**实例层**：`GraphStore` 的 incremental 模式只会新增/更新节点与边。
如果出现一张新表（比如 `labevents` 要进图谱），必须有人改 `objects.yaml` 再重跑——
没有流程，也没有校验，更没有"谁确认的"记录。

## 2. 设计：overlay + 提案脚本 + 人工确认

```text
新表/新需求
   │
   ├─ 智能体或人提出 spec（name / table / keys / attributes / sensitivity / relation）
   │
   ├─ scripts/propose_object.py 校验（表存在、主键在列里、敏感级合法、关系 on 合法）
   │
   ├─ 人工确认（--apply --yes）
   │
   ├─ 写入 governance/graph/objects.local.yaml（只追加，不覆盖）
   │
   └─ 下次 run.py：load_model() 自动合并 overlay → 图谱写上新对象
```

为什么要 overlay 而不是直接改 `objects.yaml`：

- `objects.yaml` 是**手写、带注释**的单一事实来源，程序改写会丢注释；
- overlay 只追加、同名直接报错，不会"悄悄改模型"；
- 审核记录天然落在 overlay 的提交历史里（谁加了什么、什么时候）。

## 3. 校验规则

| 检查 | 规则 |
|---|---|
| 表 | 必须在本次运行的 `schema_snapshot.json` 里（ingest 阶段写） |
| 主键 | 必须是该表真实列（唯一性由图谱的 `GRAPH_DUPLICATE_NODE` 兜底） |
| 敏感级 | 只能是 L1/L2/L3 |
| 关系 | `on` 必须是起点对象的主键，且是目标表的列 |
| 命名 | 对象/关系不能与已有模型重名（overlay 不覆盖） |

## 4. 演示（10 人队列，已复现后删除 overlay）

```powershell
# 1) 先跑一次，生成 schema_snapshot.json
python run.py --cohort-size 10 --llm off --output output_dyn10

# 2) 预览新增（不写文件）
python scripts/propose_object.py --snapshot output_dyn10/governance/metadata/schema_snapshot.json `
  --table labevents --name LabEvent --keys labevent_id `
  --attributes itemid,charttime,valuenum,valueuom,flag --sensitivity L2 `
  --concept "一次检验结果" --relation-name has_lab_event `
  --relation-from Encounter --relation-on hadm_id

# 3) 确认写入
... --apply --yes

# 4) 再跑一次：图谱写上 LabEvent
python run.py --cohort-size 10 --llm off --output output_dyn10
```

## 5. 局限（诚实写）

1. **新表仍需 ingest 加载**：本演示用的是已加载的 `labevents`；真正的新文件（如 `transfers`）
   还要先在 `ingest.py` 里加读取与过滤，这一步没有自动化；
2. **主键唯一性没有在脚本里验证**：没有数据时只能查"列存在"，唯一性交给 `verify` 的
   `GRAPH_DUPLICATE_NODE`（error）兜底；
3. **对象发现仍靠人触发**：脚本不会自动扫"有哪些新表"，需要人指定 `--table`；
4. overlay 目前只支持"加对象/加关系"，不支持改已有对象（那是另一类变更，需要走评审）。
