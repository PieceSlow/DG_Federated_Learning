# 08 · 协作与代码约定

## 1. 分支与提交

| 场景 | 做法 |
|---|---|
| 新功能/改流程 | `feat/<主题>` 分支，一次提交只做一件事 |
| 修 bug | `fix/<主题>` 分支 |
| 文档/排版 | 直接改 `docs/`，可提到 `main` |
| 合并 | 先本地跑 `python -m unittest discover -s tests -t .`，再发起合并 |

提交信息用一句话说清"做了什么、为什么"：

```text
feat(quality): 增加 stay_id 孤儿检查并给出置空规则
fix(assemble): 处方缺 drug 名称时留空而不是报错
docs: 补充 ICU 挂接率的口径说明
```

**不要提交**：`output/`、任何 parquet/csv、本机绝对路径截图（见 `07-数据与合规.md`）。

## 2. 目录与命名

```text
governance/<阶段>.py            一个治理环节一个模块
governance/meds.py              横切的规范适配（schema/编码/划分）
governance/context.py           运行上下文
tests/test_<模块>.py            与被测模块同名
tests/synthetic.py              合成数据，供端到端测试
```

- 新增阶段：在 `governance/` 下建模块，实现 `run(ctx)`，再到 `pipeline.STAGES` 注册
  （含 `requires`），并补一条集成测试。
- 所有路径：**不要在代码里硬编码本机目录**。从 `config.py` 取默认值，或用参数/环境变量。
- 新增产物：同时更新 `.gitignore` 判断（是否含患者行）、README 产物表与对应 `docs/`。

## 3. 代码风格

- Python ≥ 3.10，`from __future__ import annotations` + 内置泛型（`list[str]`、`int | None`）；
- 行宽建议 ≤ 120；缩进 4 空格；文件 UTF-8 无 BOM、LF 换行；
- 公共函数写 docstring，说明"为什么这样做"而不只是"做了什么"；
- 关键取舍（截断、只标记不修正、聚合行血缘）要写进注释或文档，评审更关心判断依据；
- 中文注释可以，但标识符、日志键名保持英文，避免跨平台编码问题。

## 4. 测试

```powershell
python -m unittest discover -s tests -t .        # 全部
python -m unittest tests.test_quality -v         # 单个模块
python -m unittest tests.test_integration_synthetic -v   # 端到端
```

约定：

- 新增纯逻辑（规则、映射、哈希划分、路径解析）时**必须**加测试；
- 端到端测试只用 `tests/synthetic.py` 的合成数据，**不要**连真实 MIMIC；
- 依赖 `flexible-schema` 的用例用 `skipUnless` 跳过，保证没装该依赖也能跑其余测试。

## 5. 环境与依赖

- 依赖只写在 `requirements.txt`；新增依赖时说明用途（必装/可选）。
- 已验证组合：Python 3.13 + pandas 3.0 + pyarrow 26 + langgraph 1.2 + flexible-schema 0.1；
  Python 3.12 + pandas 2.2 + pyarrow 16 + langgraph 1.2 也可通过全部测试。
- Windows 路径统一用 `pathlib.Path`，参数里可以写 `F:/xxx` 或 `F:\xxx`。
- 国内网络装依赖卡住时加镜像：`-i https://pypi.tuna.tsinghua.edu.cn/simple`。
