# 本地运行与密钥

## 1. 填 API key（只放本地，不入库）

```powershell
cd code_repo
Copy-Item .env.example .env
notepad .env
```

在 `.env` 里填一行：

```text
DEEPSEEK_API_KEY=sk-...
```

- `.env` 已加入 `.gitignore`，不会提交；
- 程序启动时自动读取 `code_repo/.env`，已存在的环境变量优先，不会被覆盖；
- 不要把 key 写进代码、prompt、文档或聊天记录；如果泄露立即在平台轮换。

也可以不用 `.env`，直接设环境变量：

```powershell
$env:DEEPSEEK_API_KEY = "sk-..."
```

## 2. 预算护栏（人民币，默认 20 元）

```text
默认：--llm-budget-cny 20
告警：花费达到 50% / 80% 时打印 [预算预警]
停止：达到 100% 时拒绝后续 LLM 调用（BudgetExceeded）
```

可显式调整：

```powershell
python run.py --llm api --llm-budget-cny 20 --llm-max-calls 200 ...
```

**max_tokens 与思考模型的坑**：智能体要一次返回 8 类对象 + 关系的 JSON（约 1.5k~2.5k tokens），
早期默认 1200 会把回复截断 → `Expecting value: line 1 column 1 (char 0)` → 自动回退到
`objects.yaml`。现在默认 `LLM_MAX_TOKENS=4000`；调过之后要清掉 `output/llm_cache/`，
否则会复用旧的截断回复。

另外 `deepseek-flash` 是**思考模型**，`completion_tokens` 里含推理 tokens：长 prompt 下
推理会吃光 4000 额度、`content` 为空（`finish_reason=length`）。结构化抽取建议
`LLM_MODEL=deepseek-chat`；即使配了 `flash`，客户端也会在空内容时自动降级到
`LLM_FALLBACK_MODEL`（默认 `deepseek-chat`）再试一次。

- 同时给 `--llm-budget-usd` 时取更小值；
- 汇率用 `--llm-usd-cny`（默认 7.2），只用于估算；
- 调用明细写入 `output/audit/llm_usage.jsonl`，预算状态在运行日志里可见。

## 3. 小批量实验

```powershell
# 先用 5~10 人验证链路，不跑全量
python run.py --cohort-size 10 --llm api --mimic-root "..." --note-root "..."
```

建议顺序：

1. `--llm off`：确定性链路，确认 12 阶段和 MEDS 校验；
2. `--llm mock`：智能体协作/驳回，零成本；
3. `--llm ollama --llm-model qwen3:8b`：本机模型，无 key、不出网（见第 4 节）；
4. `--llm api --llm-budget-cny 20`：云端模型，小批量；
5. 通过后再扩大到 100 人。

## 4. 本机 Ollama（无 key、零费用、不出网）

```powershell
ollama list                       # 确认模型，如 qwen3:8b
python run.py --cohort-size 20 --llm ollama --llm-model qwen3:8b
```

| 项 | 默认 | 覆盖方式 |
|---|---|---|
| 端点 | `http://127.0.0.1:11434` 的**原生** `/api/chat` | `--llm-base-url` |
| 思考 | **关闭**（`think:false`） | — |
| 上下文 | 16384（请求级 `options.num_ctx`） | `LLM_NUM_CTX` |
| 超时 | 900 秒 | `--llm-timeout` |
| 输出上限 | 4000 | `--llm-max-tokens` |
| 费用 | **0**（本地推理不计费，只计调用次数） | — |

**实测（qwen3:8b，RTX 4070 Laptop 8 GB，20 人队列）**

| 项 | 结果 |
|---|---|
| 总耗时 | **301.7 秒**（对齐 88s、对象化 155s） |
| LLM 调用 | 5 次（aligner / object_finder / relation_extractor ×2 / graph_critic） |
| tokens | 15,143 prompt + 2,238 completion，名义费用 0.0072 USD（本地实际 0） |
| 字段对齐 | **1 轮通过**，8 条映射 |
| 对象识别 | 7 类对象（Patient/Encounter/ICUStay/Diagnosis/Prescription/Procedure/ClinicalNote） |
| 关系抽取 | 6 条关系，GraphCritic 提意见后重试 1 次通过 |
| 图谱 | `model_version=agent-proposal` —— 图确实由模型提案建成，8 类对象 / 9 类关系 |
| 数据产物 | 6,015 事件 / 82 告警 / 0 error，与确定性运行一致 |

## 5. 当前重构边界

- 有出处的依据：MIMIC 原始表 + **助教提供的 MEDS 源码**（`third_party/meds`，只规定列与
  目录布局，不含事件清单）+ Lab4 任务文本；
- 本组自定（不是外部规定）：对外事件清单（`meds_targets.yaml` 的 11 类）、`命名空间//值`
  写法、对齐目标字段与各类阈值；
- 字段对齐目标：`governance/alignment/target_schema.yaml`（8 个源字段）；
- 匹配器：`matchers.py` / `combine.py` / `select.py`，输出 auto/review；
- `derived_fields.csv` 记录聚合/派生字段，不参与匹配；
- 自造聚合（`n_diagnosis`、`total_los_days` 等）归入标签/特征层，不参与 MEDS 字段匹配。
