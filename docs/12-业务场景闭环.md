# 12 · 业务场景闭环：心衰患者 30 天再入院

> 对应 `Lab4/对象化和标签.md` 里"业务需求 → 概念模型/对象"（L47）和
> "标签支持业务"（L76）两条，用一个具体问题把 **对象 → 标签 → 视图** 串起来。
> 目的不是做临床研究，而是证明：治理产物（图谱/标签/360）能回答一个业务问题。

## 1. 业务问题

> 心衰住院患者出院后 30 天内再入院的比例是多少？哪些已有标签和再入院相关？

- **场景**：临床科研/随访资源分配——出院后早期识别高风险患者，安排随访。
- **不碰原始表**：只读治理产物（对象图谱节点、患者 360、KV 标签）。

## 2. 对象 → 标签 → 视图

```text
业务问题：心衰 30 天再入院
   │
   ├── 对象（图谱）
   │     Encounter（admittime / dischtime）
   │     Diagnosis（ICD-9 428* / ICD-10 I50*）
   │     Patient（gender / anchor_age）
   │
   ├── 标签（KV，打在对象上）
   │     L1.sensitivity（共享边界）
   │     L2.elderly / L4.comorbidity_burden / L4.polypharmacy
   │     L4.frequent_admitter / L4.drug_intensity
   │
   └── 视图（一行一个患者）
         hadm_id / index_dischtime / readmitted_30d / days_to_next_admit
         + 人口学 + 标签
```

产物（`output/governance/scenario/`，gitignored）：

- `hf_readmission_view.csv`：业务视图，32 行；
- `hf_readmission_summary.json`：队列数、阳性数、标签覆盖、口径说明。

脚本：`scripts/scenario_hf_readmission.py`（只读治理产物，可复现）。

## 3. 口径

| 项 | 口径 |
|---|---|
| 心衰 | ICD-9 `428*` / ICD-10 `I50*`（**编码级**，不是临床确诊） |
| 索引住院 | 该患者**最早**的心衰住院 |
| 30 天再入院 | 索引住院出院后，同一患者下一次住院的 `admittime − dischtime ≤ 30 天` |
| 标签 | 代理口径（见 `docs/05`），缺失 = 未打标，**不是 false** |

## 4. 结果（100 人队列，2026-11-18）

- 心衰队列 **32 人**；30 天内再入院 **7 人（21.9%）**；
- 年龄均值 70.9 岁，女 17 / 男 15；再入院者距出院中位 **16 天**（0–25 天）；
- 患者划分：train 28 / held_out 4（按患者划，无泄漏）。

### 标签 × 再入院

| 标签 | 有标签（再入院/人数） | 无标签（再入院/人数） | 备注 |
|---|---|---|---|
| `L4.polypharmacy` | 7/28（25.0%） | 0/4 | 多重用药 |
| `L4.comorbidity_burden ≥13` | 7/19（36.8%） | 0/13 | 中位数切分 |
| `L4.frequent_admitter` | 7/22（31.8%） | 0/10 | **与结局同源**（标签由住院次数定义），不能当预测因子 |
| `L2.elderly` | 5/22（22.7%） | 2/10（20.0%） | 基本无差异 |

## 5. 局限（必须写在报告里）

1. 心衰是**编码级**定义，未做临床确认；
2. 样本 32 人、阳性 7 例，**没有统计效力**，只能证明流程能跑通；
3. 标签阈值是代理值（如多重用药 ≥40 种药），不是临床标准；
4. `L4.frequent_admitter` 与再入院**同源**（都来自住院次数），不能作为预测特征，
   表里列出是为了说明"标签之间的依赖关系要审"；
5. 没有依从性/随访数据，`对象化和标签.md` 里"不爱吃药"那种业务标签暂时造不出来；
6. 只覆盖 MIMIC 单库，没有跨中心验证。

## 6. 怎么复制到下一个场景

1. **定结局**：如"术后 30 天并发症""糖尿病血糖达标"；
2. **选对象**：从图谱里挑出承载该结局的对象（Encounter/Procedure/Lab…），
   没有的对象先在 `objects.yaml` 加，再重跑 08；
3. **选标签**：优先用现有 KV；没有就加 `definitions.yaml` 一条规则（说明是代理口径）；
4. **写视图脚本**：照 `scenario_hf_readmission.py`，只读治理产物，输出一行一主体的 CSV。
