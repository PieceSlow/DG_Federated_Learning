# 02 · 数据接入与标准化

## 1. 队列抽样

**做法**：取 `icustays` 中 `subject_id` 最小的 N 名患者（默认 100），再把这些患者在所有源表中的
**完整历史**取出。

**为什么不随机抽样、也不取"前 N 行"**：

- 随机抽样不做固定种子 → 不可复现，与治理要求冲突；
- 取前 N 行 → 截断患者历史，检验序列不完整（早期版本踩过这个坑）。

**大表扫描算法**（`ingest.scan_for_subjects`）：分块读入，只保留队列行；过程中探测
`subject_id` 是否非递减——若是，读到超过队列最大 ID 就提前停止；一旦发现乱序就继续扫到 EOF，
保证不漏行。这比"全量载入再过滤"省内存，也比"只读前缀"正确。

## 2. 源表清单与角色

| 表 | 粒度 | 关键字段 | 用途 |
|---|---|---|---|
| `patients` | 1 行/患者 | `gender`、`anchor_age`、`anchor_year` | 人口学事件、患者 360 |
| `admissions` | 1 行/住院 | `admittime`、`dischtime`、`hospital_expire_flag` | 住院对象、时间窗 |
| `icustays` | 1 行/ICU 停留 | `stay_id`、`intime`、`outtime`、`first_careunit` | 队列来源、ICU 对象 |
| `diagnoses_icd` | 1 行/诊断 | `icd_code`、`icd_version`、`seq_num` | 诊断事件与标签 |
| `procedures_icd` | 1 行/操作 | `icd_code`、`chartdate` | 操作事件与标签 |
| `prescriptions` | 1 行/处方 | `formulary_drug_cd`、`starttime`、`dose_val_rx` | 处方事件 |
| `labevents` | 1 行/检验 | `itemid`、`charttime`、`valuenum`、`valueuom` | 检验事件 |
| `d_labitems` / `d_icd_*` | 字典 | `label`、`long_title` | 编码可读描述 |
| `discharge` | 1 行/小结 | `note_id`、`charttime`、`text` | 文本事件 |

清单会落成 `output/governance/metadata/data_source_inventory.csv`，含粒度、主键、内容、敏感级别、
读取行数与读取方式（全量 / 流式）。

## 3. 编码命名空间

MEDS 只要求 `code` 是字符串，跨中心对齐必须自己定规范，因此统一为 `命名空间//值`，并强校验
格式（`meds.CODE_RE`：首段必须大写，之后至少一个 `//值` 段）。

| 前缀 | 示例 | 说明 |
|---|---|---|
| `LAB//MIMIC_ITEM//itemid//UNIT` | `LAB//MIMIC_ITEM//50912//MG_DL` | 单位进编码，便于区分同项目不同单位 |
| `DIAGNOSIS//ICD10//I10` | `DIAGNOSIS//ICD9//4019` | 保留 ICD 版本，避免 v9/v10 混码 |
| `PROCEDURE//ICD10//0B110Z4` | `PROCEDURE//ICD9//9671` | 手术/操作，与诊断同样保留 ICD 版本 |
| `MEDICATION//MIMIC_FORMULARY//CODE` | `MEDICATION//MIMIC_FORMULARY//ASPIRIN` | 用药品目录编码而非自由文本药名 |
| `ADMISSION//HOSPITAL`、`DISCHARGE//HOSPITAL`、`ICU_DISCHARGE//HOSPITAL` | — | 就诊边界事件 |
| `GENDER//F`、`DEMOGRAPHIC//ANCHOR_AGE` | — | 人口学静态事件（`time` 为空） |
| `NOTE//DISCHARGE` | — | 出院小结原文 |
| `NOTE_SECTION//<KEY>` | `NOTE_SECTION//DISCHARGE_DIAGNOSIS` | 小结章节正文 |
| `NOTE_DIAGNOSIS//DISCHARGE` | — | 逐行出院诊断 |
| `NOTE_MEDICATION//<SLUG>` | `NOTE_MEDICATION//ASPIRIN` | 出院用药行 |

命名空间不是散落在代码里的字符串：它们集中声明在
`governance/alignment/meds_targets.yaml`（`code_namespaces` / `code.template`），
标准化阶段按声明产出事件，`alignment/interface.check_events` 再校验**实际发出的命名空间
是否都被声明、必填列是否真的非空**。新增一个命名空间必须同时改声明，否则 `INTERFACE_*`
告警会把它抓出来。

另外，诊断本身没有发生时间，MEDS 事件用住院时间 `admittime` 兜底（声明里写明
"不是诊断时刻"），因此 `DIAGNOSIS` 事件的 `time` 不再是空值。

`metadata/codes.parquet` 为每个编码补描述：检验取 `d_labitems.label`，诊断取
`d_icd_diagnoses.long_title`，其余按规则生成（`meds.code_description`）。

## 4. 对象索引与事件挂接

标准化阶段先在内存里建对象索引（Patient / Encounter / ICUStay 的键与时间窗），再让每条事件挂上
`hadm_id` / `stay_id`：

- `patients` → 人口学事件（患者级）；
- `admissions` → 入院/出院事件（住院级）；
- `icustays` → 入科/出科事件（ICU 级）；
- `diagnoses_icd` / `prescriptions` / `labevents` / `discharge` → 挂到住院，能落 ICU 窗口的再挂 `stay_id`。

对象模型本身在 07 对象化阶段固化为治理资产；标准化阶段只保留"事件挂接需要的索引"。

## 5. 文本分支

`text_extraction.py` 只做三件确定性的事：

1. 按 MIMIC 出院小结的标准章节头切分；
2. `DISCHARGE DIAGNOSIS` 段落逐行产出诊断事件；
3. `DISCHARGE MEDICATIONS` 段落对编号行做"药名 + 剂量"正则解析，产出用药事件。

长度上限：原文 20,000 字符、章节 4,000、单行 500。截断是有损的，报告里明确写"已截断"。

**断言检测**：诊断/用药行按规则打 `assertion` 标签（否定 > 家族史 > 历史性 > 假设），
例如 ``No chest pain`` → `negated`、``Family history of diabetes`` → `family`。
单标签设计，暂不支持"家族史 + 否定"这类复合断言。

**一致性检查**：出院用药与结构化处方比对（`TEXT_DRUG_MISMATCH`）、
出院诊断文本与 ICD 描述比对（`TEXT_CODE_MISMATCH`）、必需章节缺失
（`TEXT_SECTION_MISSING`）；只标记，不改写原文。

**为什么不用大模型**：本机 deepseek-r1:14b（Ollama）实测约 4–5 token/s，单份小结需数分钟，
155 份要约 5–15 小时，且输出含 `<think>` 与 Markdown 代码块，还需要 JSON 修复环节。
规则版可复现、可审计、无网络依赖。后续若要接 LLM，只需替换 `_extract_text` 中的抽取函数，
返回 `{code, text_value}` 列表即可，校验与落盘逻辑不变。

## 6. 取舍与已知局限

| 取舍 | 理由 |
|---|---|
| 保留原始 `subject_id` 不重编号 | 只有保住原始 ID，才能与其它产物对账、回溯 |
| 诊断没有时间就留空 | 不臆测时间，避免制造虚假时序 |
| 处方缺药品编码时不输出事件，只记告警 | 编码是跨中心对齐的前提；硬编码药名会污染事件流 |

局限：文本规则只覆盖有标准章节头的小结；编码未做术语归一（无 UMLS 文件）；ICD 与药品编码
未映射到 OMOP/RxNorm。
