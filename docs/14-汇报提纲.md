# 14 · 汇报提纲（12 页）

> 每页给"要点 + 配图 + 一句话讲稿"，数字用 100 人队列（2026-11-18）。
> 图从 `output*/graphs/` 取；表从 `output/governance/` 取。

## P1 封面

- 标题：**基于 MIMIC-IV 与 UMLS 的医疗数据治理：从多源对齐到对象图谱与标签**
- 副标题：12 阶段流水线 · 声明驱动接口 · 多智能体建图 · 业务场景闭环
- 讲稿：我们做的不只是"把表拼起来"，而是一条可复现、可审计的治理链。

## P2 场景与目标

- 多中心临床研究协作：本地 EMR 标准化 → 受控共享 → 联邦建模；
- 目标：数据**能关联**（字段对齐）、**能理解**（UMLS 概念）、**能管理**（分级/目录）、**能支持业务**（标签/视图）。
- 配图：`docs/01` 的架构图（或文字版 12 阶段）。

## P3 流水线 12 阶段

- 接入 → 组织标准化 → 质量 → 事件仓储 → 汇聚 → 对齐 → 概念 → 对象化 → 标签 → 分类分级 → 编目 → 报告；
- 每阶段产物落盘，`run_summary.json` + `audit/` 可追。
- 讲稿：所有阶段都跑在 LangGraph `StateGraph` 上，默认 `--llm off` 可复现。

## P4 MEDS 接口：声明驱动

- `meds_targets.yaml` 是唯一声明：11 类事件 × 5 列 = **55 行接口台账**；
- 声明 × 匹配结果 × 实际事件流三方核对：`unmapped 0`、未声明命名空间 0、必填空缺 0；
- 实测：**148,336 条事件、3,892 个编码、14 个命名空间**。
- 配图：`output/governance/mapping/field_level_meds.csv` 截取（或 docs/02 表）。

## P5 字段对齐

- 8 个目标字段、4 个匹配器（名称/类型/结构/取值，权重 0.45/0.25/0.15/0.15）；
- 38 条映射（auto 22 / review 16），其中 19 条被 SQL 消费；
- 用映射生成 SQL，SQLite 逐列对账 **42 列 0 差异**。
- 讲稿：映射不是"表名像就接"，每条都有证据和匹配分。

## P6 对象模型（UML 类图）

- 8 类对象、9 条关系；主键/属性/来源表/敏感级都在类图上；
- 配图：`output/graphs/graph_classes.png`；
- 讲稿：这张图回答了"每个对象是什么、和谁什么关系、数据从哪来"。

## P7 多智能体建图

- 链条：ObjectFinder → RelationExtractor → 本地执行 → GraphCritic；
- **api 实测**（10 人，`deepseek-chat`）：ObjectFinder 提 7 类、RelationExtractor 提 6 条 →
  GraphCritic 重试 1 次 → 8 类/9 关系；成本约 **$0.03**；
- 证据：`audit/agent_trace.jsonl` 逐步记录 decision/tokens；`--llm off` 时回退确定性模型。
- 讲稿：LLM 提议、代码执行、校验驳回、可回退——不是"让模型自由发挥"。

## P8 概念层（UMLS）

- 编码 → CUI（UMLS 2026AB，1.2M 概念）；
- 覆盖率 **84.3%**（ICD10 99.6% / ICD9 94.4% / ICD10PCS 99.4% / RXNORM 88.8% / LNC 39.8%）；
- 概念节点 **2,259（CUI 2,039 + 编码级兜底 220）**；标签概念对象与图谱命中率 **99.96%**；
- 讲稿：同义词合并靠 CUI，映射不到的不猜，降级为编码级但仍可 join。

## P9 标签体系（L1–L4）

- **136,723 条标签、19 个 tag_key**；L1 敏感级别 / L2 记录级（含断言、确定性）/ L3 概念级 / L4 患者级；
- 医学标签强化：`L3.cui` 2,039 条、`L3.semantic_type` 取 UMLS STY；
- 配图：`docs/05` 标签表（或 `tag_dictionary.csv`）。

## P10 分类分级与编目

- 8 条分级规则、7 条落地；`patient_360` 单列 C08/L3（患者级视图）；
- 编目 8 类资产（字段级 L1 / 记录级 L2 分开）、五级目录；
- 共享边界：**去文本事件表**（剥离 NOTE 正文）才能受控共享；
- 讲稿：级别只有一个来源（`classification/result.csv`），编目不允许自己写级别。

## P11 业务场景：心衰 30 天再入院

- 心衰 **32 人**、30 天再入院 **7 人（21.9%）**；
- `comorbidity_burden ≥13` 组 **36.8%** vs 0%；`polypharmacy` 25% vs 0%；
- 诚实标注：`frequent_admitter` 与结局同源，不能当预测因子；样本无统计效力；
- 配图：`output/governance/scenario/hf_readmission_view.csv` 截取（或 docs/12 表）。

## P12 局限与下一步

- 局限：HF 编码级定义、样本小、LNC 映射低、动态分级未做、对象发现靠人触发；
- 下一步：**动态分类分级**（触发→重评→生效→留痕）、动态对象（新表→对象）、LNC 归一；
- 收尾：可复现（240+ 测试、`--llm off` 默认）、可审计（audit/）、可扩展（声明/overlay）。
